# AI 공동개발 규칙

AI는 구현 보조 도구이며 변경의 검토와 병합 책임은 사람에게 있습니다.

## 작업 시작 전

1. 최신 `dev`와 관련 Issue를 확인합니다.
2. 목표, 작업 범위, 제외 범위와 완료 조건을 확인합니다.
3. 예상 변경 파일, 검증 방법과 위험을 먼저 정리합니다.
4. 팀에서 결정되지 않은 사항은 질문하거나 `Pending`으로 남깁니다.

## 작업 중

- Issue 범위를 넘는 기능이나 리팩터링을 추가하지 않습니다.
- 기존 파일은 먼저 읽고 필요한 부분만 수정합니다.
- 새 dependency, 제품 아키텍처, 데이터 schema와 인증 방식을 임의로 결정하지 않습니다.
- 혜택 정보와 출처를 추측해서 생성하지 않습니다.
- API 키, 토큰, 개인 환경, 개인정보와 AI 대화 원문을 저장소에 넣지 않습니다.
- AI가 제안한 코드는 사람이 diff와 주요 동작을 직접 검토합니다.

## 검증과 PR

- 테스트 성공 여부는 실제 명령 결과로만 기록합니다.
- 실행하지 못했거나 환경상 생략한 검증은 이유를 명시합니다.
- PR에는 사용한 AI 도구와 범위, 사람이 검토한 부분, 알려진 위험을 기록합니다.
- 완료 보고에는 변경 파일, 실행한 검증, 실행하지 못한 검증, 위험과 후속 작업을 포함합니다.

AI 대화에서 확정된 결과는 목적에 맞게 변환합니다.

- 해야 할 일: GitHub Issue
- 중요한 기술 결정: ADR
- 구현과 검증 결과: Pull Request
- 현재 실제 상태: `docs/current-status.md`
- 반복 실행 규칙: `CONTRIBUTING.md`, `AGENTS.md` 또는 관련 docs
