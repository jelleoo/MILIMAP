# AI 공동개발 규칙

AI는 구현 보조 도구이며 변경의 검토와 병합 책임은 사람에게 있습니다. 이 문서는 특정 AI 도구나 프롬프트 형식을 강제하지 않고, AI를 사용할 때 지켜야 할 공통 안전 규칙만 정의합니다.

## 지시 우선순위와 충돌

지시가 충돌하면 다음 순서로 판단합니다.

1. GitHub 브랜치 보호, 보안과 비밀정보 규칙
2. 현재 Issue의 승인된 범위와 완료 조건
3. `AGENTS.md`, `CONTRIBUTING.md`, Accepted ADR과 관련 정책 문서
4. 현재 작업 요청
5. 기존 코드, 테스트와 스타일
6. 안전한 기본값

현재 작업 요청이 상위 규칙과 충돌하면 임의로 우회하거나 범위를 확대하지 않고 충돌 내용과 필요한 결정을 보고합니다.

## 작업 요청과 범위

- 작업 전 최신 `dev`, 관련 Issue와 직접 영향을 받는 파일을 확인합니다.
- 목표, 작업 범위, 제외 범위, 완료 조건, 예상 변경 파일, 검증 방법과 위험을 확인합니다.
- 제품 동작이나 기술 방향이 달라지는 결정은 임의로 확정하지 않고 승인받거나 `Pending`으로 남깁니다.
- Issue 범위를 넘는 기능이나 리팩터링을 추가하지 않습니다.
- 예약되지 않은 파일이 필요하면 `docs/team-workflow.md`에 따라 충돌과 병합 순서를 확인합니다.

## 변경 안전 원칙

- 기존 파일과 구조를 먼저 읽고 필요한 부분만 수정합니다.
- 기존 도구로 해결할 수 있는데 dependency를 추가하지 않습니다.
- 핵심 아키텍처, DB 방식, 신규 외부 라이브러리, 인증 방식, API 계약, 데이터 스키마를 임의로 변경하지 않습니다.
- 혜택 정보와 출처를 추측해서 생성하지 않습니다.
- API 키, 토큰, 개인 환경, 개인정보와 AI 대화 원문을 저장소에 넣지 않습니다.
- 충돌 시 `ours` 또는 `theirs` 전체 선택, 강제 push와 다른 브랜치 변경 삭제를 임의로 수행하지 않습니다.

## 검증과 보고

- 변경 위험에 맞춰 가장 좁은 검증부터 수행하고, 필요할 때 관련 테스트·lint·빌드로 범위를 넓힙니다.
- 테스트 성공 여부는 실제 명령 결과로만 기록합니다.
- 실행하지 못했거나 환경상 생략한 검증은 가능한 정적 검토와 diff 확인으로 보완하고 이유와 남은 위험을 명시합니다.
- AI가 만든 변경도 사람이 diff와 주요 동작을 검토하고 책임집니다.
- PR과 완료 보고에는 변경 파일, 실행한 검증, 실행하지 못한 검증, 알려진 위험과 후속 작업을 기록합니다.

## 협업

Issue, branch, worktree, 파일 예약, 공용 핵심 파일, 병렬 작업과 병합 순서는 `docs/team-workflow.md`를 따릅니다. AI 도구의 선택, 프롬프트 형식과 세부 작업 방식은 팀원이 상황에 맞게 선택할 수 있습니다.
